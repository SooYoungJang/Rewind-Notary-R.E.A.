# Rewind Notary (R.E.A.)

레아가 등장하는 Unity 2D 횡스크롤 액션 프로젝트다. 이 저장소에는 Unity 프로젝트가 최상위에 있다. 초기 단일 스테이지의 조작과 구현 설명은 아래 기록으로 남겼다.

## Unity에서 열기

1. [Unity Hub](https://unity.com/download)에서 Unity **6.0 LTS 6000.0.65f1**을 준비한다. 정확한 버전은 [ProjectVersion.txt](ProjectSettings/ProjectVersion.txt) 기준이다. 다른 버전으로 열 때는 별도 복사본에서 먼저 검증한다.
2. Unity Hub → Projects에서 디스크의 기존 프로젝트를 추가한다. **이 README와 `Assets/`, `Packages/`, `ProjectSettings/`가 나란히 있는 저장소 폴더**를 선택한다. `Assets/`만 선택하거나 `unity/RewindNotary/` 하위 폴더를 찾을 필요는 없다.
3. 패키지 다운로드, 에셋 임포트, 스크립트 컴파일이 끝날 때까지 기다린다. 의존성은 [Packages/manifest.json](Packages/manifest.json)에 기록돼 있다.
4. [Main 씬](Assets/Scenes/Main.unity)을 열거나 메뉴에서 **Rewind Notary → Open Main Scene**을 선택한다. **Play**를 누르고 Game 뷰에 포커스를 둔다.

## QA 상태

[QA 31 수정 보고서](QA31-FIX-REPORT.md) 기준:

- **구역별 자동 플레이:** Windows Unity Player **6000.0.65f1** 기반 테스트 복사본에서 오페라·대종루·화랑을 새 슬롯으로 각각 단독 실행했다. 세 구역 모두 저장 지점 10/10, 사망 0회였고 최종 저장 데이터를 확인했다. 출시 빌드나 사람이 처음부터 끝까지 플레이한 결과는 아니다.
- **연속 실행:** 제공된 **6000.6.9f1** 빌드에서 메인 구간부터 화랑까지 한 번에 끝내는 실행은 미확인이다. 위 단독 실행을 이어 붙여 완주로 간주하지 않는다.
- **정적 검사:** 지형·구역 검사 3,788개가 통과했다. 전체 검사기 [`tools/validate_gamedev.py`](tools/validate_gamedev.py)는 원본 작업 트리 구조와 이 저장소에 빠진 파일(예: `tools/localization_followup.py`, 보호 파일 해시 목록)에 의존한다. 이 저장소에서 전체 검사를 완료했다고 볼 수 없으며, 실행하려면 해당 의존 파일이 포함된 원본 트리가 필요하다.

## 초기 프로토타입 기록

아래 조작표, 구현 범위, 수치와 점검 동선은 초기 단일 스테이지의 기록이다. 현재 캠페인의 조작이나 진행 조건을 설명하는 문서가 아니다. 초기 실행 환경의 한계는 [초기 구현 보고서](BUILD-REPORT.md)를 참고한다.

### 조작

| 동작 | 키 |
|---|---|
| 좌우 이동 | A / D 또는 ← / → |
| 점프 | Space, W 또는 ↑ |
| 짧은 점프 | 상승 중 점프 키 놓기 |
| 검 공격·4단 콤보 | J, Z 또는 마우스 왼쪽 버튼을 연속 입력 |
| 전체 재시작 | R |

코요테 타임과 점프 버퍼는 각각 **0.1초**다. 플레이어 체력 6, 보스 체력 12이며 플레이어 콤보 데미지는 **1 / 2 / 3 / 4**, 보스 검 타격은 1이다. 1~3단 중 다음 입력을 예약하거나 동작 종료 후 0.18초 이내 다시 누르면 이어진다. 착지·피격·시간 초과 시 콤보 연결이 초기화되며, 4단은 넉백·히트스톱이 강하다. 공중 공격 중에는 이동 관성과 방향 전환이 유지된다. 자세한 입력 창과 변경·검증 내역은 [FEEDBACK-REPORT.md](FEEDBACK-REPORT.md)를 참고한다.

보스의 황금색 점멸은 0.45초 공격 예고다. 피격에는 짧은 경직·넉백·무적 시간이 있다. 사망하면 1.1초 후 복귀하며, 낙하하면 즉시 복귀한다. 아레나 진입 후에는 아레나 시작점에서 플레이어와 보스 체력을 초기화한다. R은 시작 지점부터 초기화한다.

### 구현 범위

- 지면 2구간, 낙하 틈 1개, 발판 7개, 시작점과 보스 아레나.
- Rigidbody2D 기반 이동/점프, 검 공격 판정, 체력·피격·복귀.
- Texture2D `Resources.Load`와 `Sprite.Create`를 통한 8×4 시트 재생. idle/run/jump/fall/land/attack 상태, 왼쪽은 flipX. Animator와 `.meta` 스프라이트 슬라이싱 없음.
- 잔향의 추적·주기적 점프·예고 후 검 공격, HUD 체력바·클리어 표시.
- **CinemachineCamera + CinemachinePositionComposer + CinemachineBrain**으로 추적. 제한된 추적 타깃으로 스테이지 범위 유지.
- 원경/중경 패럴랙스와 반복 지면. 타일을 번갈아 좌우 반전하여 연결 경계를 맞춘다.
- 코드 합성 WAV 효과음 9종·루프 BGM 2종. SFX 풀·필드/보스 BGM 크로스페이드와 타격 히트스톱·화면 흔들림·흰색 플래시. 연결/파라미터/검증 한계는 [SOUND-REPORT.md](SOUND-REPORT.md) 참고.
- 스토리 진행·시간 회귀 시스템·새 인물·새 설정은 추가하지 않았다. HUD는 기본 폰트 호환을 위해 영어다.

두 시트는 2048×768이며 정확한 8×4 격자(셀 256×192)를 사용한다. 코드에서 정수 셀 Rect와 프레임별 발 피벗 JSON으로 읽는다. 원본 발 기준선에는 최대 12픽셀 편차가 있어 피벗으로 지면을 맞추며, 이미지 자체의 중심·프레임 연속성은 추가 보정 대상이다.

### 당시 PC 점검 항목

1. Console의 컴파일 오류와 `Missing GameArt`가 없는지 확인한다.
2. idle/run/점프/착지/검 프레임, 오른쪽·왼쪽 표시와 발 위치를 확인한다.
3. 발판 끝을 벗어난 직후 점프, 착지 직전 점프 입력, 짧은 점프를 각각 시험한다.
4. x=16~20의 틈에서 점프 통과와 낙하 복귀를 시험한다.
5. 아레나 진입, 보스 예고/공격/점프, 양쪽 체력 감소, 사망 복귀, 보스 처치 후 R을 시험한다.
6. 화면 비율을 바꾸며 카메라와 배경 반복 경계를 확인한다.
7. [사운드 보고서의 실행 검증](SOUND-REPORT.md#unity에서-남은-실행-검증)에 따라 루프·예고 취소·타격 플래시·사망/재시작 후 시간 배율을 확인한다.

이후에는 시트의 중심/발 위치와 잔상 정리, 발판 이동 감각·공격 판정·보스 템포를 Unity에서 조정하는 순서를 권장한다. 이 프로젝트는 액션의 기본 동작을 확인하는 프로토타입이며 출시용 콘텐츠나 빌드가 아니다.
